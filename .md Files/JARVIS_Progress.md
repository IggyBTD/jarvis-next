## 2. What JARVIS is right now

A Tauri 2 desktop app (Rust backend, Vite plus vanilla JS frontend, no framework). Iron-Man-style HUD with a node-mesh sphere, hardware telemetry, a local-LLM chat through LM Studio with four model presets, markdown and LaTeX rendering, sandboxed artifacts, a memory vault and habit system, privacy switches, and a frameless window with custom controls. The "whiteboard" is a workspace of floating panels (see below), reached by the Coding / Finance preset or a temporary button.

### Screen anatomy (all in `index.html`, one file with inline CSS)
- **Header:** a single 1 px cyan line across the top (32 px strip, no fill) that continues down into a 220 px wide, 24 px deep notch with steep sides (one continuous stroke, centre y = 31.5). The notch has no text. The strip holds only the window buttons at the top right: temporary Library button, minimize, maximize/restore, close. The strip is the window drag region.
- **Left column:** CPU metrics, CPU core grid (8 cores), RAM, storage and network cards.
- **Right column:** engine configuration card (five mode buttons) and a GPU card.
- **Bottom right:** MODEL // ACTIVE INSTANCES panel, one card per loaded LM Studio model (a second card appears if two are loaded).
- **Centre:** the 48-node mesh sphere; under it the chat (boxless transcript plus a short underlined input). When a conversation starts the sphere lifts 24vh.
- **Bottom centre dock:** four round buttons: microphone, attach files, internet access, network link.

### Design system (applied to everything; whiteboard panels reuse the same tokens)
Tokens in `:root` of `index.html`: colours `--bg #01080e`, `--text-1..4`, `--accent #79e0f2`, `--accent-line #00d9ff`, `--danger #ff3344`, `--line*`; spacing `--s-1..6` (4, 8, 16, 24, 32, 48); type scale **12, 14, 16, 18, 22, 28 px** (raised one notch in session 2 because the user struggled to read the HUD; telemetry readouts use `--fs-lg` 18 px in `--text-1`, labels 14 px, card titles 12 px), side panels `--panel-w` 400 px, core cells `--core-h` 40 px, mode buttons `--mode-h` 48 px; a compact media query (window under 820 px high or 1440 px wide) restores the old scale 11, 12, 14, 16, 20, 24 and 320 px panels so small windows still fit; motion `--dur-fast 150`, `--dur 200`, `--dur-slow 250 ms` with `--ease-out` and `--ease-in-out`. One accent colour (cyan; red only for errors, the close hover and the "off" ring on dock toggles). Contrast measured against #01080e: text-1 17.3, text-2 13.2, text-3 8.4, text-4 5.7, control borders 3.8. No `transition: all`; progress bars and core fills animate `transform`. Visible 2 px focus ring on every control, `aria-label`s on icon buttons, `aria-pressed` on toggles, `role="log"` on the transcript, a global reduced-motion rule. Impeccable's detector reports 15 findings (7 card titles flagged twice for 11 px and tracking, which are uppercase labels kept at 11 px because 12 px makes two headers wrap; 1 for the fixed-size shell). The neon cyan palette is intentional and outranks the generic design skills.

The user wants nothing drawn in the webview's or OS's own style. ### Chat and LM Studio (`src/core/llm-client.js`, `chat-ui.js`, `model-panel.js`)
- `llm-client.js` is the only code that calls LM Studio. Streaming `/v1/chat/completions` with client-side timing (time to first token, generation t/s, prompt t/s).
- **Model swapping:** native API `/api/v1/models`, `/models/unload`, `/models/load`. Every other loaded chat model is unloaded and confirmed gone before the target loads; a failed unload aborts the load; swaps are queued and the target is read when the swap runs (rapid clicks collapse to the last choice). Models already loaded at app start stay loaded until the first button click or message.
- The system prompt is `config/system-prompt.md` (formatting rules for ChatGPT-like prose, the `<jarvis-artifact>` convention, bright colours for artifacts, quote Mermaid labels). Each turn also appends a `<user-habits>` block and a `<recalled-memory>` block (see Memory).
- Slash commands typed in the input run locally and never reach the model (section "Memory and habits"). Typing `/` opens a menu above the field (`core/command-palette.js`) listing every command with a one-line explanation; it narrows as you type. Up/Down choose, Tab or Enter complete (Enter runs it once the name is complete), Esc closes, a click completes. The list is the `COMMANDS` array in `core/commands.js` (name, args, description, group): add a command there and a handler in `handlers`, and it shows up in the menu and in `/help [word]` by itself. About 39 commands (conversation: `/clear /new /retry /copy /attach /detach`; view: `/mode /modes /whiteboard /panels /artifacts /open /reload`; info: `/help /status /model /time /date`; plus the memory, voice and agent ones). Checked in headless Chrome only (`tools/ui-checks/command-palette.cjs`, 23 checks), not yet in the real Tauri window.
- Transcript: model replies left, your messages right, no bubbles, your text slightly greener, dim timestamps; a collapsible THOUGHT PROCESS block shows the model's reasoning stream; `content-visibility: auto` on messages keeps long conversations cheap. Auto-scroll only follows while you are within 48 px of the bottom.
- Rendering (`src/core/markdown.js`): marked + KaTeX (`$`, `$$`, `\(..\)`, `\[..\]`) + highlight.js (14 languages) + DOMPurify, all bundled locally. Code blocks have a language header and COPY. Links in replies are inert (they must not navigate the app window).
- Attachments (`attachments.js`, `file-extract.js`, rebuilt in session 2): plain text and code, **PDF** (pdf.js, loaded on first use, text layer only: a scanned PDF is refused with a message), **Word .docx, PowerPoint .pptx, Excel .xlsx** (own small zip reader plus regex over the XML, no dependency) are turned into text and sent inside `<attached-file name="...">` blocks (the system prompt tells the model they are data). Images (max 10 MB) go as image parts and auto-switch to the visual model. All text attachments of a message share a 48,000 character budget (`TEXT_BUDGET`); a longer file is cut and the block says `truncated="first N of M characters"`. Old .doc/.xls/.ppt and other binaries are refused. A refused file is shown as a red NOT ATTACHED line in the attach row (it used to be only a tooltip, which looked like nothing happened). Verified against the real models in Chrome: txt, pdf, docx, xlsx answered correctly by qwen3-14b; a PNG reached qwen3-vl-8b.

### Artifacts (`tool-router.js`, `artifacts.js`, `artifact-renderer.js`, `whiteboard.js`)
The model wraps visual or reusable output in `<jarvis-artifact id type title lang>`. Types: html, svg, mermaid, chart (Chart.js JSON), markdown, code. `tool-router.js` splits a reply into text and artifact parts on every streamed chunk (handles half-written tags). Same id = new version. Each artifact renders in `<iframe sandbox="allow-scripts">` (no same-origin) with a CSP of `default-src 'none'`; verified blocked from inside: parent access, localStorage, cookies, external fetch, LM Studio fetch, CDN scripts. Mermaid is rendered to SVG in the app, Chart.js is inlined (a parent-origin `blob:` script URL does not work in an opaque-origin iframe). Chart animation is off (it stalls when animation frames are throttled). SAVE uses the native dialog plus fs plugin in the desktop app and a plain download in a browser. **The artifact viewer UI is not visible right now** because whiteboard mode is cleared (below); the code, store and cards in the transcript still work.

### Memory and habits (`src-tauri/src/memory.rs`, `instincts.rs`, `src/core/memory-client.js`, `commands.js`, `config/memory.json`)
- Memory vault: markdown files at `<project>/memory/<project|user>/<kind>/<id>.md` (override root with env `JARVIS_MEMORY_DIR`), JSON-valued frontmatter, schema `jarvis.memory.v1`, kinds context / decision / fact / handoff / lesson / note / preference / runbook. Create-only writes, secret-shaped text refused before writing, ids validated, symlinks never followed, body max 4 KB, scan cap 5000 files with a `truncated` flag, malformed files reported and never deleted, `memory/.gitignore` auto-created. `memory/` does not exist until the first save.
- Habits (instincts): `<project>/memory/instincts/<project|global>/<id>.md`. One trigger, one action, confidence (default 0.7). Only habits at or above 0.7 are sent to the model (max 6). Created and changed only by explicit user commands; no background observer.
- Recall: each turn searches project-scope memories (4 results, 1800 characters) and wraps them in `<recalled-memory>` marked as untrusted data; angle brackets in stored text are neutralised.
- Commands: `/help`, `/remember [--user] [--kind k] [--tags a,b] text`, `/memories [query]`, `/forget id`, `/habit [--global] [--domain d] when X => Y`, `/habits`, `/habit+ id`, `/habit- id`, `/unhabit id`, `/promote id`, `/memory`.

### Privacy switches and dock (`switches.js`, `dock-ui.js`)
`switches.js` patches `window.fetch`: globe off refuses JS fetches to anything but this machine; wifi off refuses all JS fetches including LM Studio. Both persist across launches (localStorage). Microphone really opens and stops `getUserMedia`, always starts off; `voice.js` consumes the stream (see "Voice"). Telemetry is Rust-side and unaffected. Attach opens a file picker.

### Telemetry (`src-tauri/src/telemetry.rs`, `src/core/telemetry-view.js`)
Rust polls LibreHardwareMonitor `data.json` every second (std::thread, no tokio) and emits `telemetry-update`. `telemetry-view.js` draws it: a missing metric shows N/A with an empty grey bar; before the first reading or after 5 s of silence every panel reads N/A and a red SENSORS OFFLINE line appears under the notch; recovery is automatic. Bars and core fills animate with `transform: scale`. RAM speed (`Memory_Frequency`) is NOT from LibreHardwareMonitor: its only memory clock data is the SPD `tCKAVGmin` (0.416 ns = DDR5-4800, the module's JEDEC baseline), which shows 4808 MHz even with EXPO on. `telemetry.rs` instead asks Windows once at start (`Win32_PhysicalMemory.ConfiguredClockSpeed` through a hidden PowerShell, fastest DIMM) and overlays it on every payload; N/A until that returns or if it fails.

### Node mesh (`src/main.js`, `src/core/mesh-state.js`)
48-node Fibonacci sphere on a canvas that is 2x its box so expansion never clips. Speech animation: `pulse()` per streamed chunk only marks speech active for 0.35 s, the swell is a 2.2 to 3.4 Hz oscillator, so 10 and 60 chunks per second look equally calm; gentle breathing while thinking; `setSpeechLevel(0..1)` is the hook for real TTS volume. Interaction: drag spins (horizontal) and tilts (vertical) with inertia; a click makes a cyan ring, a bloom, an outward spring kick on the nearest nodes and brighter links; mouse parallax tilt. Hit test uses the canvas rect at event time and is skipped in whiteboard mode; the render loop is skipped there too.

### Window (`src/core/window-controls.js`, `src-tauri/tauri.conf.json`)
`"decorations": false`. Custom minimize, maximize/restore (icon follows `isMaximized()`), close. Capabilities in `src-tauri/capabilities/default.json`: window minimize / toggle-maximize / maximize / unmaximize / is-maximized / close / start-dragging, `dialog:allow-save`, `fs:allow-write-text-file`. Default window is still 800x600 (the HUD wants a large window).

### Whiteboard (session 2: panel engine built; see also the decisions block below)
`body.wb-mode` is a full-window mode of the main window. **Empty, it is the grid plus three things:** the header (line, notch, window buttons), the bottom dock (mic, attach, internet, network link; the same element and position as on the HUD) and the chat input, which is the HUD's own `#hud-chat-input` with no whiteboard overrides: same position, 420 px width, underline style and font as on the HUD (the user first asked for a framed 240 px centred field, then asked for it to match the HUD; do not restyle it per mode). No empty-state text, no layout toolbar, no EXIT button (the user asked for those to go). The board (`#whiteboard`, left 24, right 24, top 76, bottom 160) is where panels float. The mesh, HUD panels and notch meta are hidden in the mode.
- **Session panel (the "works like Claude Code" part):** once there is a conversation, a SESSION panel shows it on the whiteboard. It holds the real `#chat-output` element (moved in on entering the mode, moved back to the HUD chat panel on leaving; streaming keeps working because `chat-ui.js` holds the element, not its position). In the session the source of every code, html and svg artifact is written out under its card (`.ac-source`, hidden on the HUD by CSS; plain text while streaming, highlighted when complete). The session takes **at least 65% of the board width** (`MAIN_SHARE` in `board-layouts.js`, rounded up to the 8 px grid) and the artifact panels (the live rendering) take the rest, stacked in rows; alone, the session fills the board. A `code` artifact (Python, Rust, ...) opens no panel of its own because the session already shows it; clicking its card still opens one. Closing the session with its X hides it until the next message.
- **Panels = artifacts.** One panel per artifact id (types html, svg, mermaid, chart, markdown, code, and the new **table**: JSON `{columns, rows}`, an array of objects, or CSV; cells use `textContent`). Each panel has a title bar (drag, double click maximises), version arrows, PREVIEW/SOURCE, COPY, SAVE, maximise, close, and resize from the right edge, bottom edge or corner. Keyboard: focus the title bar, Alt + arrows move by 8 px, Alt + Shift + arrows resize. Positions snap to the 8 px grid and are clamped inside the board. Narrow panels hide secondary buttons (container queries).
- **Model control (the only way layouts are chosen now):** after the artifacts, the reply may carry `<jarvis-board layout="split|rows|main-side|grid|cascade" panels="id1,id2" focus="panels" />` (the layout applies to the space beside the session; `focus="panels"` flips the shares so panels get 65% and the session 35%, meant for finance and research) (documented in `config/system-prompt.md`). It is applied only when the reply is complete (`chat-ui.js`, `applyBoardSpec`). Listed panels stay in that order (first = main), unlisted panels are closed (their artifacts stay in the chat cards), unknown ids and layouts are ignored. Without the tag the arrangement is 'auto': panels stack in rows beside the session (or tile when there is no session); a newly opened artifact re-runs it. Any manual drag, resize or key move clears the active layout, so later panels cascade instead of re-running it.
- **Behaviour:** panels persist when you leave the mode (Esc or the Library button) and are still there on re-entry. Clicking the Coding / Finance preset or sending a message in it enters the mode; other presets leave it.

### Voice (session 3: Nemotron 3.5 ASR Streaming 0.6B for listening, Kokoro 82M for speaking)
**Update after the first real-window test (same session):** it works in the Tauri window. Fixes made from that test: the capture node now runs through a zero-gain node to the output (the first version showed LISTENING but recognised nothing in the window; this is the likely cause, not proven); the 160 ms-chunk Nemotron build replaced the 560 ms one (words appear one at a time about 0.5 s after the speech starts, final text about 1 s after the last word; 560 ms was about 0.9 s and 1.7 s; the 560 ms folder is still in `models/voice`, switch back via `config/voice.json`); end-of-sentence pause 0.9 to 0.7 s; British voices (b*) now use their own Kokoro engine with the British lexicon (loaded on first use), American ones the US lexicon; a 0.16 s pause between spoken sentences; the system prompt has a "Spoken replies" rule that applies only when `chat-ui.js` adds a `<voice-mode>` marker. The sidecar log (`sidecars/voice/voice.log`) now shows audio frames, peak level and decode time every 3 s: the user's mic peaked at exactly 1.000 (clipping, input gain probably too high). Decode takes about 52 ms per 160 ms chunk.
**End of a message (text-aware, session 3 follow-up):** a fixed silence timer sent messages mid-thought, so sherpa's built-in endpointing is off (`enableEndpoint: 0`) and `server.mjs` decides itself. How long a silence must last depends on the words so far (`pauseFor` in `sidecars/voice/util.mjs`, tests in `voice-sidecar.test.mjs`): after punctuation that ends a sentence 0.4 s (`complete`), after a question or request shaped sentence with at least 5 words 0.5 s (`likely`; the model rarely writes the final ? or . before you stop), after an ordinary word such as a noun 0.7 s (`unsure`; it was 1.0 s until the take-back below made a mistake recoverable), and after a hanging ending 2.5 s (`open`): a comma, "...", a connective or article or auxiliary (and, but, the, a, to, is, um, uh, well, so, I, ...) and also a verb that still needs its object (create, build, show, explain, and by suffix -ate/-ize/-ise/-ify such as simulate or visualize, with a short list of nouns excluded). The user was cut off at "...create an artifact that will simulate" with the earlier 0.65 s rule; the real-audio test for exactly that sentence (1.6 s pause, with and without noise) now passes. Silence is measured from the audio energy (a chunk is speech when it is louder than 2.5 times the 20th percentile of the last 5 s, minimum 0.006 RMS) and the model must also report at least 0.25 s of trailing blanks (one blank frame = 80 ms, `num_trailing_blanks`), or the model alone reports the full time; never while the text is still changing; 30 s hard cap. Measured here: a finished sentence is sent about 0.4 to 0.7 s after the last sound (was about 1 s with model blanks alone), a sentence ending on "a" about 2.1 s later, a 1.8 s mid-thought pause after "to" does not split the message, also with room noise of 0.02 (uniform, fairly noisy); at 0.05 it splits. The trade-off is yours to tune in `config/voice.json`: lower numbers feel quicker but risk sending a thought you were still forming. A message cannot be unsent.
Chosen by the user. Both run through **sherpa-onnx** (`sherpa-onnx-node` 1.13.8, the official native addon; Nemotron 3.5 needs 1.13.5 or newer) on the CPU, in a **separate Node process** (`sidecars/voice/server.mjs`) so the models and native libraries can never take the HUD down. It listens on `127.0.0.1:8765` (`config/voice.json`) and only accepts local origins.
- **Models** (in `models/voice/`, git-ignored, 1.0 GB unpacked, official k2-fsa release assets): `sherpa-onnx-nemotron-3.5-asr-streaming-0.6b-560ms-int8-2026-06-11` (tag `asr-models`, 475 MB archive; the 160 ms build `...-160ms-int8-2026-06-11` is the one in use now; multilingual, 40 locales, automatic language detection, punctuation and capitals) and `kokoro-multi-lang-v1_0` (tag `tts-models`, 350 MB archive, full precision; the smaller int8 build `kokoro-int8-multi-lang-v1_0`, 132 MB, was offered and not chosen; it names its model file differently, so switching needs a small change in `resolveTts` in `sidecars/voice/util.mjs` as well as the folder name in `config/voice.json`). Re-download: `https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/<name>.tar.bz2` and `.../tts-models/kokoro-multi-lang-v1_0.tar.bz2`, then `tar -xjf` inside `models/voice`. Other chunk sizes of Nemotron (80, 160, 320, 1120 ms) exist; 560 ms is the one chosen. Licence of the Nemotron weights: NVIDIA OpenMDW-1.1 (keep the attribution if redistributed).
- **Sidecar protocol** (header of `server.mjs`): `GET /health`, `GET /voices`, WebSocket `/asr` (16 kHz int16 PCM in, `partial` / `final` text out; the sidecar detects the end of an utterance after 0.9 s of silence) and `/tts` (JSON `speak` requests in, float32 audio frames out per sentence, `cancel` stops generation). `--parent-stdin` makes it exit when the app dies (tested: exit code 0 when the pipe closes).
- **Rust** (`src-tauri/src/voice.rs`): `voice_start` finds the project folder, reuses a sidecar already answering on the port or spawns `node sidecars/voice/server.mjs --parent-stdin` with no console window and a log in `sidecars/voice/voice.log`; `voice_stop` kills it. Needs `node` on PATH (or env `JARVIS_NODE`). Dev-only path logic: it walks up from the working directory to `config/system-prompt.md`, so a packaged build would need a bundled Node sidecar (not done).
- **Frontend:** `voice-client.js` (only module that talks to the sidecar: `ensureSidecar`, `createListener` with an AudioWorklet at 16 kHz in `pcm-worklet.js`, `createSpeaker` with gapless WebAudio playback and a level analyser), `voice.js` (orchestration, preferences in localStorage `jarvis.voice`), `speech-text.js` (pure: markdown, code, tables, formulas, urls and the `<jarvis-artifact>` / `<jarvis-board>` markers are not spoken, half-written ones are held back, sentence splitting that survives 3.5, e.g., Dr. and file.js). `chat-ui.js` has four small hooks (`beginTurn()`, `speech.push / end / abort`, `bindChat`).
- **Behaviour:** microphone switch on = voice conversation. The field's placeholder shows STARTING VOICE... then LISTENING... (it is the only new visible element; no dock button was added). Words appear in the field while you speak, text already typed there is kept in front. A finished sentence is sent like a typed message; the reply is spoken sentence by sentence as it streams (only the visible answer, not the thought process); the mesh follows the loudness of the audio (`setSpeechLevel`). **Half duplex:** from sending until the last word is spoken plus 350 ms, no audio reaches the recognizer, so it cannot hear itself (no barge-in by voice; echo cancellation is not verified). Mic switch off = silence and the sidecar's sockets close; typed replies are not spoken unless `/speak on`. If the sidecar or a model is missing the mic switches itself off and a VOICE OFFLINE line says why. `/voice [name]` (plays a sample), `/voices`, `/speak on|off|stop`, `/speed 0.5-2`, `/lang auto|en|de|...`. Default voice `bm_george` (British male); the voice id order was checked against the docs and by measuring the pitch of all 53 names.
- **Measured (this machine, Ryzen 7 7800X3D, 4 threads each):** recognizer loads in 1.6 s, synthesizer in 1.1 s; Kokoro makes 4 s of speech in about 0.9 s (real-time factor 0.22), so the first sentence starts about a second after it is complete; streaming partials trail the speech by about 0.6 s, the final text comes about 1.5 s after the last word. A round trip (Kokoro speaks, Nemotron hears) was exact except that synthetic "pod" was heard as "pard" once. Memory use of the sidecar was not measured.
- **Tests:** `tools/tests/speech-text.test.mjs` (8, incl. "any chunking gives the same sentences"), `tools/tests/voice-sidecar.test.mjs` (helpers always; with the models installed it starts its own sidecar on port 18765: both models load, foreign origin refused over http and WebSocket, speak-then-transcribe round trip, cancel, unknown voice), `cargo test --lib` (2 new in `voice.rs`), and `node tools/ui-checks/voice-keys.cjs` (real Chrome, fake microphone playing a Kokoro-spoken question, STUBBED LM Studio so the real one is never touched: 21 checks, needs the dev server and a running sidecar; it replaced the older voice-flow.cjs after sending became manual).

### Whiteboard design decisions (session 2, user-approved; step 1, the panel engine, is built, web panels are not)
- The whiteboard is an adaptive workspace of panels. The model decides which panels to open and how to arrange them; we provide building blocks only (artifact, code, table, markdown, terminal output, notes, later web panels driven by a Playwright sidecar).
- **Floating panels** (not tiled). The model declares panels and a layout from a small vocabulary (not pixel coordinates), via a `<jarvis-board>`-style marker; the app validates, snaps to the grid and rejects bad output.
- **Manual control is allowed in full** (drag, resize, close, focus) as a possibility; model placement is the default.
- Clicking the Coding / Finance preset opens the whiteboard instantly (built, `chat-ui.js`); sending a message in that preset also opens it (already so). The other presets leave it.
- Build order: panel engine without sidecar, then the coding scenario (code left, live prototype right), then web panels with the confirm gate and audit log.

## 7. Known gotchas (learned the hard way)

- **After `npm install` or Cargo changes, restart `npm run tauri dev`.** A webview opened before new dependencies were optimised shows raw markdown and broken imports.
- **Vite `?t=` module duplicates:** after a file is edited, Vite serves it (and its importers) with a `?t=timestamp` URL, so a console `import('/src/core/x.js')` can create a second module instance with separate state. Take the exact URL from `performance.getEntriesByType('resource')`.
