# Decisions

One line each. Newest at the bottom.

- D-01 Commits are per phase (P0..P12) on branch `jarvis-build`, not per step; each commit has a green `npm test`. A per-step history was not worth 65 commits for a single unattended pass.
- D-02 Folder: everything is built inside the existing JARVIS Next repo. The old front end in `src/` is kept (it is the HUD/chat app); the new server, agent and shared code are new top-level folders `server/`, `agent/`, `shared/`, `tests/`. The build brief's `next/` and `app/` folders do not exist here: `app/` maps to `src/` (see D-10).
- D-03 Config lives in `config/server/` because `config/` already holds files the old app imports with the same names (`models.json`, `actions.json`, `voice.json`).
- D-04 Browser sidecar is `sidecars/browser-guard/` because `sidecars/browser/` is the existing Intel-page sidecar; the existing one is untouched.
- D-05 Node 22+ (the dev machine runs 24). Test globs need it.
- D-06 Dependencies added: `ws`. `playwright` was already a dependency (the guarded sidecar uses it). Tests use `node:test` only.
- D-07 Thinking toggle: default `chat_template_kwargs: { enable_thinking: false }` in the request body, which llama-server and LM Studio pass to the Qwen3 chat template. `thinkingMethod` also supports `no_think` (appends `/no_think` to the last user message) and `request_field` (`reasoning_effort`). Verified only against the mock; confirm on the PC (HUMAN_TODO).
- D-08 Audit days are UTC dates. The chain spans days (first line of a day points at the last hash of the previous day).
- D-09 `actions.json` is generated once by `scripts/gen-actions.js` and is the contract afterwards (re-running keeps the `enabled` flags). Time tools (`set_timer`, `set_reminder`, `list_schedules`) are marked `internal`: they run on the server, not on an agent.
- D-10 Front end: the existing `src/` app is the client. A setting (Settings, "JARVIS server") switches it between its original local mode (LM Studio direct, local tools, this computer only) and server mode (the server owns the model, tools, approvals and conversation; the app draws what arrives). The two modes are exclusive, so two action runners never both reach a machine; in server mode a failed connection never falls back to local tools or the local model.
- D-11 The UI token is kept in localStorage in both the browser and the desktop build. An OS keychain needs a Tauri plugin or a Rust crate that cannot be built and checked unattended here, so it is a human step (HUMAN_TODO.md section 10). The global push-to-talk shortcut is likewise registered by the desktop build once voice (P9) is enabled.
- D-12 `wake_on_lan` exists as a Tauri command (src-tauri/src/wol.rs) because a browser cannot send UDP; the agent also has a `wake_on_lan` action for waking the other machine from a running one.
- D-13 The built app (`dist/`) is served by the JARVIS server itself, so a browser on the Mac needs nothing installed. A token in the URL #fragment is saved once and removed from the address bar (`scripts/client-link.js` prints the link). The static files hold no secrets; every data route still needs a token.
- D-14 The globe's aircraft data comes through the server in server mode (`server/osint/opensky.js`, routes under `/api/osint/`), because OpenSky refuses browser pages and the OpenSky login should stay on the PC. The old Intel sidecar keeps its own copy of the same logic and is untouched (the original local mode still uses it). Ship data (aisstream.io) is already fetched by the page itself, so its key is entered once per device.
- D-15 The Mac needs only a small bundle (`node scripts/make-mac-bundle.js`, about 80 KB): the agent, its sidecars, config and setup scripts, chosen from the real import graph. No Tauri app, no models, no tests, no tokens. Its prompt is `docs/MAC_PROMPT.md`.
- D-16 `machines.mac.host` in the PC's `config/server/machines.json` must be the Mac's address (the PC calls the Mac agent there); `server.url` in the Mac's copy must be the PC's address (OpenCode on the Mac reaches the model there). The server also listens on loopback, so the PC's own app works whatever its network address does.
- D-17 Saved chats in server mode are the server's conversations (`data/conversations/`): the sidebar lists, opens, renames, pins and deletes them through `/api/conversations`. `sessions.js` switches on `serverMode()`, so the original local mode (Rust store) is unchanged. The server keeps the chat; the window only remembers which one is open and redraws its last 30 messages on reload.
- D-18 Memory on the server is a short list of notes (`data/memory.json`, 50 notes of 300 characters) that the model writes with `remember` and removes with `forget`. They are shown on every turn as data from the user, never as instructions, and are tier T1 because the harm of a planted note is bounded by that framing and the cap; the user can read and delete them (`list_memories`, `forget`). The old Rust vault and instincts are not ported.
- D-19 The Mac updates itself with `node scripts/update.js`: it downloads `/api/bundle` from the server with its own machine token, unpacks it with a small zip reader, keeps `data/` and its own `config/server/machines.json`, runs `npm install` only if `package.json` changed, and restarts the LaunchAgent. The server builds the bundle on request (cached 60 s).
- D-20 The guarded browser tries the installed Google Chrome, then Edge, then Playwright's own Chromium, so no 150 MB download is needed. OpenCode is started as its real program (`opencode.exe` next to the npm shim on Windows), because a `.cmd` shim cannot be started without a shell.
- D-21 Not ported to server mode: plan mode and skills (local features of the original chat), a file tree and diff view of the other computer on the Code page (the Code page's task list shows the coding agent's tasks instead), the Rust memory vault. Voice engines on :8770/:8771 are a human step (HUMAN_TODO.md section 9).
- D-22 Waking a sleeping PC from another network needs a device on the PC's own network, so the design is a relay (`scripts/wake-relay.js`) that holds one MAC and one token and sends the Wake-on-LAN packet when asked over Tailscale; `scripts/wake.js` asks it and waits for the server's port. No port forwarding. Nothing here changes BIOS, adapter or power settings: `wake.js --check` only reads them. The packet code is shared (`shared/wol.js`) with the agent's `wake_on_lan` action.
- D-23 The LaTeX pad (Ctrl+L) converts symbol typing locally (`shared/latex.js`, no model, instant) and asks the model only when words are left over (`/api/latex` in server mode, the local model otherwise). The old Ctrl+L (jump to the message field) moved to Ctrl+J.

## 2026-10-25 Model tuning (27B vs Coder)
Qwen3.8-27B thinking is switched off with the top-level request field reasoning_effort none (chat_template_kwargs enable_thinking has no effect on this LM Studio). A thinking budget in the model's remembered settings (llm.prediction.reasoning.budgetTokens) works for API requests. Load settings that lms load has no flag for (KV cache type, MoE expert layers, batch size, thinking budget) are written into LM Studio's remembered per-model config, backed up in docs/lmstudio-settings-backup-2026-10-25. Recommended model: the 27B with thinking off and MTP 2 at 64k; see docs/bench-results-2026-10-25.md. models.json was not switched; only contextLength (65536) and the sampling block changed.

models.json now points at unsloth/qwen3.8-27b: thinkingMethod request_field with every use false (reasoning_effort none, also for OpenCode via the proxy), sampling 0.3 / 0.95 / 20 / 0 / 0 / 1.0, contextLength 65536, mtp.enabled true (documentation only; MTP is a load setting in LM Studio). Tests pin their own thinking policy (tests/helpers.js, p2-model, p7-digest) so they do not depend on which model models.json names.

## 2026-10-25 Model menu in server mode
The chip in server mode is now a working menu: GET /api/models lists what the PC's LM Studio has installed (loaded ones marked), POST /api/model loads the chosen model, unloads the others (409 while a reply is running), and switches the request settings to that model's profile in models.json (profiles; a model without one gets thinking off and LM Studio's own sampling). The choice is saved in data/active-model.json and applied at start. Only llm-client.js talks to LM Studio. The system prompt carries the date only; the time is added to the newest user message in the request (not stored), so the prompt prefix stays the same and LM Studio's prompt cache is reused.

## 2026-10-26 LaTeX mode replaces the LaTeX pad
D-23 is replaced: Ctrl+L no longer opens a window. It turns LaTeX mode on and off, with a "LaTeX" chip beside the input. In the mode, symbol-only text sent from the ordinary input is converted locally (`shared/latex.js`) and sent between $ signs; text with words is sent as typed. The /api/latex route stays but nothing in the app calls it.
